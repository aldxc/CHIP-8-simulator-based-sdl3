# CHIP-8-simulator
## 开发文档（Development）

本节为 CHIP-8-simulator 的详细开发文档，面向实现者。仅覆盖实现说明、模块关系和工程化细节（不包含示例代码）。当前目标为一个标准的 Windows 版本（Visual Studio 2022）；后续可以扩展其他平台或特性。

### 目标与范围
- 目标：实现一个准确、可测试、可维护的 CHIP‑8 模拟器，使用 C++14 与 SDL3（SDL3 用于窗口、输入与音频）。
- 范围：实现标准 CHIP‑8 功能（包括 64×32 显示、16 键输入、定时器、堆栈和所有原始指令）。SCHIP 或高分辨率扩展为可选特性，后续通过配置启用。

---

### 项目架构概览
本项目应分为清晰的模块并保持依赖单向：

- `chip8::core`（核心模拟器）
  - 功能：内存、寄存器、指令解码与执行、堆栈、定时器、键状态接口、显示缓冲接口、ROM 加载与状态快照。
  - 要求：不能依赖 SDL3；所有外设交互通过抽象接口（例如键状态查询、显示更新回调）完成，便于单元测试。

- `chip8::platform`（平台适配层 — Windows/SDL3 实现）
  - 功能：窗口与渲染（SDL3 纹理上传/缩放）、事件处理（将 SDL 事件映射到 CHIP‑8 键）、音频播放、文件系统（ROM 加载）、配置加载。
  - 要求：实现必须以接口实现（实现类）注入到 `chip8::core`。

- `chip8::ui`（可选）
  - 功能：运行时菜单、ROM 选择、调试 UI（寄存器观察器、断点、逐步执行）

- `tests`（测试套件）
  - 功能：单元测试、集成测试和回归测试。应与核心模块紧密集成，使用 mock/stub 替代 SDL3。

交互原则：核心（core）通过最小接口暴露：`LoadROM`, `Reset`, `Step`, `RunForCycles`, `SetKeyState`, `GetDisplayBuffer`, `Snapshot`, `Restore`。

### 核心子系统详细实现说明
下面对每个核心子系统给出实现要求与边界处理建议（纯文本，便于在实现中引用）。

1. 内存与 ROM
- 内存大小固定 4096 字节（0x000–0xFFF）。
- 程序加载起始地址 0x200。加载时检查 ROM 大小，若超出剩余内存返回错误。
- 字体表在 `Reset` 时写入内存（默认地址 0x050，可在实现中作为常量）。
- 内存访问必须校验边界：任何越界操作记录错误并引发可控的错误返回或断言（测试模式下应抛异常以便定位）。

2. 寄存器与堆栈
- 使用 `uint8_t V[16]` 存储 V0–VF，`uint16_t I` 存储索引寄存器，`uint16_t PC` 存储程序计数器。
- 栈使用固定深度（16），`uint16_t stack[16]` 与 `uint8_t sp`（或 `int`）管理。对溢出/下溢有明确的错误处理策略（记录日志并在测试/调试模式触发断言，生产模式可返回错误码）。

3. 指令取指与解码
- 取指：从 PC 读取两个字节（大端），默认 PC += 2。特殊指令可修改 PC（如跳转、调用），必须避免重复增加。
- 解码器应采用表驱动或分支树（switch-case）实现，代码要可测试：把每个 opcode 的语义实现为独立可调用函数，便于单元测试。
- 未知或非法指令：记录 ERROR 级日志并根据配置选择忽略、抛异常或停止执行。

4. Fx0A（等待键输入）实现策略
- 行为规范：执行到 Fx0A 时，CPU 必须等待直到任意一个键被按下，然后将该键值存入指定寄存器后继续执行下一个指令。
- 实现建议：`Step` 函数在执行 Fx0A 时返回 `Status::WaitKey`（或类似状态）；上层平台层在主循环继续处理 SDL 事件，检测到键按下后调用 `SetKeyState` 并再次调用 `Step`，使其继续；不要在 CPU 内部直接阻塞 UI 线程。

5. 绘图（Dxyn）语义与边界
- 绘图使用 XOR 操作；若清除任何像素则 VF=1，否则 VF=0。
- 默认行为应支持 wrap-around（当像素超出画面右/下边界时回绕到左/上），但应通过配置开关以支持不回绕的实现或 SCHIP 行为。
- 显存抽象：提供一个逻辑像素缓冲（例如 `std::vector<uint8_t>` 每像素一字节或位压缩），供平台层读取并上传到纹理。

6. 定时器（delayTimer、soundTimer）
- 两个计时器以 60Hz 固定频率递减（若 > 0 则每 1/60s 减 1）。
- 在主循环使用高精度计时器（`std::chrono` 或 SDL 高精度计时 API）触发计时器更新；不要把计时器递减绑定到指令执行次数。
- `soundTimer > 0` 时，平台层负责播放声音（方波或短促 beep）。音频的起停由 `soundTimer` 的状态控制。

### 平台（SDL3）集成要点（Windows）
- 依赖：在 Windows 上使用 vcpkg 或手动安装 SDL3。README 中应包含 `vcpkg install sdl3` 指令与如何在 Visual Studio 中配置依赖的步骤。
- 窗口与渲染：
  - 使用 SDL3 创建窗口（支持可变窗口大小）。
  - 使用一个逻辑像素缓冲（64×32 或 128×64），每帧将其上传为 SDL3 纹理并在渲染器上绘制。避免在每帧逐像素调用绘制命令。
  - 缩放策略：优先整数字体缩放以避免像素模糊；当窗口大小非整数倍时可选择像素邻近或平滑放大（配置项）。
- 事件与按键映射：
  - 提供默认映射（例如键盘 `1-4`, `Q-R`, `A-F`, `Z-V` 对应 CHIP‑8 `0x1..0xF`），但映射应可配置。
  - 在事件循环中仅更新 `SetKeyState`，不要在事件处理逻辑中直接驱动 CPU，除非处理 Fx0A 的等待唤醒。
- 音频：当 `soundTimer > 0` 时，启动音频播放（例如播放小范围的方波或 beep 样本）；当计时器为 0 时停止。实现可以使用 SDL3 音频设备播放循环样本或使用回调合成。

### 主循环与同步策略
- 分离三条速率路径：
  1. CPU 执行速率（`cyclesPerSecond`，可配置，推荐 500-700 Hz）。
  2. 定时器更新速率：固定 60 Hz。
  3. 渲染速率：通常 60 FPS 或与显示垂直同步一致。渲染可以低于 CPU 速率。
- 主循环建议流程：
  1. 处理 SDL 事件（窗口/键/文件等）
  2. 更新键状态
  3. 计算自上次循环以来应执行的 CPU 周期数并调用 `RunForCycles(n)` 或循环调用 `Step`。
  4. 根据时间片更新 delay/sound timers（每 1/60s）
  5. 如有显示更新或到达渲染间隔则上传显示缓冲并渲染
  6. 限制帧率或睡眠以节省 CPU（使用高精度等待）
- Fx0A 情况：当 `Step` 返回 Wait 状态时，跳过 CPU 周期执行步骤但继续处理事件与渲染；当检测到按键时恢复执行。

### 调试、日志与快照
- 日志分级：ERROR/WARN/INFO/DEBUG。调试构建启用 DEBUG，发布构建限制 INFO+。
- 在关键错误路径（未定义指令、越界访问、堆栈溢出）记录日志并在测试模式下使其可触发断言。
- 状态快照（Snapshot/Restore）：快照必须包含内存、寄存器、PC、I、堆栈、timer 值、按键状态与显示缓冲。快照用于保存/恢复和回放测试。
- 指令跟踪：提供可选的跟踪日志输出（指令编码 + 寄存器变更），便于回溯 bug。

### 测试策略（必须）
- 单元测试：
  - 解码器各分支、每条指令语义、边界条件（堆栈/内存）、Fx0A 的阻塞行为。
  - 使用 mock 平台实现替代 SDL3，以便在 CI 中运行无需图形环境的测试。

- 集成测试：
  - 对一些已知 ROM 或自定义测试 ROM 验证显示输出、计时器行为及基本互动。

- 自动化与 CI：
  - 在 CI 中运行 CMake 构建、单元测试、静态分析（clang-tidy、cppcheck）与格式检查（clang-format 或 .editorconfig 校验）。

### 构建（Windows/Visual Studio 2022）
- 推荐使用 CMake 管理构建并在项目中提供 `CMakeLists.txt`。
- 使用 vcpkg 安装 SDL3：在 README 中记录 `vcpkg install sdl3` 以及如何在 CMake 中引用 vcpkg 工具链。
- Visual Studio 配置：确保 __C/C++ > Language > C++ Language Standard__ 设置为 `ISO C++14`。
- 建议在项目中添加 Debug 与 Release 配置，Release 中关闭调试日志并启用优化。
